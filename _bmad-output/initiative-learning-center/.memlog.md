- (requirement) R1 (FR-1, FR-2): Employees can search and narrow the in-scope learning information available to them, with result type and source visible.
- (requirement) R2 (FR-3, FR-4): Employees can open authorized information and view only personal records matched to them and permitted by the approved access policy.
- (requirement) R3 (FR-5, FR-6): Authorized learning administrators can manually create and update in-scope learning items and employee records, with validation and attribution.
- (requirement) R4 (FR-7, FR-8): Learning Center can import agreed information automatically from one approved source and safely repeat imports without uncontrolled duplicates.
- (requirement) R5 (FR-9): Authorized administrators can inspect the last synchronization outcome and actionable errors.
- (constraint) RULE-1 (PRD RULE-1): Imported and manual records retain source provenance and last update details.
- (constraint) RULE-2 (PRD RULE-2): Employee-linked records are visible only to the employee and roles approved by the organization.
- (constraint) RULE-3 (PRD RULE-3): Field ownership and conflict behavior are defined before a field is both imported and manually editable.
- (constraint) RULE-4 (PRD RULE-4): Import failures are visible and do not silently erase the last good state.
- (constraint) RULE-5 (PRD Q-2): Production use waits for organizational approval of data classification, access, retention, and regional handling.
- (assumption) The first release supports a central learning catalog and employee-linked records; exact record types remain unconfirmed.
- (assumption) A learning administrator can enter and correct records manually.
- (question) The source-system inventory and example SharePoint folder contents are unknown; verify the candidate source before integration.
- (question) Identity, access, retention, regional handling, and numeric success targets remain open before production.
- (decision) 2026-11-11 — Identity and access was previously planned as the first epic; Python backend and React frontend were the only settled technical direction at that point.
- (decision by coach) 2026-11-11 — Under the users delegated request to decide and prepare the team, establish the Django REST plus React Router SPA baseline with the versions recorded in the architecture spine. This is a development decision, not an identity, data-governance, source-access, or production-hosting approval.
- (decision by coach) 2026-11-11 — Put the application foundation epic first in build order and start four independent work packets: local scaffold, identity and access policy, learning catalog field dictionary, and candidate SharePoint verification.
- (decision by coach) 2026-11-11 — Select English and Spanish UI text, a user-selectable locale, original-language source content without machine translation, and WCAG 2.2 Level AA as the development baseline.
- (constraint) Use only synthetic identities and learning data locally. Do not connect real employee data or enable production access until the required organizational approvals are recorded.
- (question) Product Owner still needs to decide which learning-item and personal-record types belong in the MVP and define measurable search, freshness, and recovery targets with source and operations owners.
- (question) IT and Security must approve identity provider, employee key, role matrix, and permissions; HR must approve personal-record fields; source owner and IT must approve SharePoint library access; Security and Privacy must approve classification, retention, and region; Operations must approve production hosting and run ownership.
