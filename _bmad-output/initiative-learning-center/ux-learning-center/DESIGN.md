# Brand & Style

No corporate design system, brand palette, typography, or product theme was provided. This file intentionally leaves visual tokens unset rather than inventing a brand. The product should feel clear, calm, and trustworthy; the employee should recognize search, record status, and source attribution without learning a new visual language.

## Colors

Unset pending the organization's design system. Status must be communicated with text or icons as well as color; color alone must not signal completion, expiry, errors, or permissions.

## Typography

Unset pending the design system. Use readable hierarchy for page title, search query, result title, metadata, and supporting help text. Avoid relying on small type for important status or source information.

## Layout & Spacing

The employee search and result content should receive the main visual emphasis. Administrative controls should be visually distinct from employee discovery. Layout and responsive breakpoints are open until the platform is selected.

## Elevation & Depth

No shadow or layering system is selected. Prefer clear grouping and borders from the adopted design system over decorative depth.

## Shapes

Unset pending the design system.

## Components

The final component tokens and visuals should inherit from the organization's approved UI system if one exists. Required component behaviors are specified in EXPERIENCE.md; this file does not choose a library.

## Do's and Don'ts

- Do preserve the same visual meaning for a status everywhere.
- Do pair status colors with text labels.
- Do show source and freshness clearly.
- Do keep employee search more prominent than administrative controls.
- Don't use color, icons, or labels to imply a certification is verified unless a source confirms that fact.
- Don't use employee performance-style scoring or rankings.
